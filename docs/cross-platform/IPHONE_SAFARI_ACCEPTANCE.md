# 真实 iPhone Safari 验收说明

目标：确认网页版在真实 iPhone Safari（以及“添加到主屏幕”后的独立窗口）能完成
世界、AI 对话、费用记录和 `.yuzhe` 备份，而不是只在桌面 Chromium 里通过。

> 本文件是操作清单，不代表已经执行。没有真实 iPhone 时，相关项目必须保留为“未验证”。

## 1. 无 Key 基础验收（不产生费用）

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | Safari 打开部署 URL | 显示产品/费用声明，不白屏 |
| 2 | 点“进入鱼者” | 进入首页，状态栏/刘海不遮挡标题 |
| 3 | 输入世界描述 → 创建世界 → 进入世界 | 世界页显示“故事从你的行动开始。” |
| 4 | 输入行动 → 点发送 | 只显示“尚未配置 DeepSeek API Key，去配置”，**不出现任何 AI 剧情** |
| 5 | 打开“设置 → 完整故事备份” | 页面可打开，显示当前世界 |
| 6 | 设置 → 网页版与数据 | 显示“添加到 iPhone 主屏幕”、存储状态、导出入口 |

如果第 4 步出现剧情文本，立即停止验收并记录截图：这说明实现退化成了假回复。

## 2. 添加到主屏幕

1. Safari 打开同一个 HTTPS 地址。
2. 点底部“分享” → “添加到主屏幕” → 名称“鱼者” → 添加。
3. 从主屏幕图标打开：
   - 不应出现 Safari 地址栏；
   - 状态栏颜色与页面协调；
   - 旋转屏幕后内容仍可读（网页版主界面为响应式，未强制锁定方向）。
4. 关闭再打开，确认仍在同一站点（数据未丢）。

## 3. Key、真实 AI 与费用（会产生 DeepSeek 费用）

> 先用一个小额度 Key，或确认账户余额可控。鱼者不代付费用。

1. 设置 → AI 服务设置 → 配置 API Key，粘贴自己的 Key。
2. 确认弹窗选择“确认保存”。
3. 点击“手动测试连接”：
   - 显示模型名、耗时、HTTP 状态；
   - 若 Key 无效，应显示“API Key 无效”，不能生成剧情。
4. 进入世界，输入短行动，确认预算：
   - 回复应**逐字/分段出现**，不是整段一次性出现；
   - 生成过程中点停止，应停止并提示“已停止请求；服务端可能已消耗 Token”。
5. 回复完成后：
   - 打开“设置 → 消费记录”；
   - 应出现模型、输入/输出 Token、缓存命中（若返回）；
   - 若未返回 usage，应显示“未估价/未知”，不能编造金额。
6. 杀进程/切后台再回来：
   - 剧情仍在；
   - Key 仍显示“已配置”（WebCrypto 持久化）；
   - 不需要重新输入。

## 4. 断网与错误处理

1. 飞行模式或关闭 Wi-Fi/蜂窝网络，再发送行动：
   - 显示网络错误；
   - **不能**出现本地假剧情；
   - 输入草稿保留。
2. 断网时刷新页面：
   - 若之前在线打开过，应能启动到首页（Service Worker 缓存）；
   - 未访问过的页面/生僻字可能缺少字体子集，属于已知限制。
3. 恢复网络后重试，应正常生成。

## 5. `.yuzhe` 导出 / 导入

1. 世界 → 备份 → 完整故事备份 → 选择保存位置。
2. iOS 会弹出系统分享面板：选择“存储到文件”，保存到“我的 iPhone”或 iCloud。
3. 确认“文件”App 中能看到 `鱼者文游故事备份.yuzhe`。
4. 导入：设置 → 导入故事 → 从本机选择文件 → 选择该 `.yuzhe`。
5. 预览应显示世界名和对话/记忆数量；确认恢复后出现新世界。
6. 如设置了密码，导入时应要求输入同一密码；错误密码不能恢复。

## 6. 长文阅读与键盘

- 进入一个有多段剧情的世界，向上滚动阅读：
  - 文字不被底部输入框永久遮挡；
  - 滚动流畅，没有横向滚动条；
  - 字体大小可读（Safari 页面缩放不应破坏布局）。
- 点输入框弹出软键盘：
  - 输入框和发送按钮保持可见；
  - 键盘收起后布局恢复；
  - 中文输入法组合文字不丢失。

## 7. PWA 缓存与更新

1. 首次在线打开后等待至少 10 秒（字体和启动资源缓存）。
2. 断开网络，从主屏幕图标打开：应能进入首页（允许字体子集缺失）。
3. 恢复网络，部署一个新版本（见 Cloudflare 教程），重新打开：
   - 新版本应在一次刷新后生效；
   - 若仍旧版，关闭标签页重开，或在 Safari 设置中清除该站点数据。

## 8. 安全边界观察

- 地址栏/分享链接中不应出现 `sk-` 或 `key=`。
- 页面不应显示已保存 Key 的明文；只显示掩码。
- Safari 开发者工具（需 Mac）Network 中，请求头可以有 `Authorization`，
  但 URL、Referer、控制台日志不应包含 Key。
- 清除网站数据后，Key 和本地世界都会被删除；应提前导出 `.yuzhe`。

## 10. 已知限制（网页版）

- 附件原文件只保留元数据，不打包二进制。
- 系统分享入口在 Safari 不可用；用“从本机选择文件”。
- Key 存储是 WebCrypto + localStorage，弱于 iOS Keychain；不要用公共设备。
- 离线字体依赖已访问页面缓存；未访问页面的生僻字可能显示为方框。
- 真实 iPhone 上如出现桌面 Chromium 未覆盖的问题，请按第 9 节记录并反馈。
