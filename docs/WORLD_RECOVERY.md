# 世界恢复、快照与分支

恢复预览使用 WorldDraftRepository 保存审核草稿。`WorldRecoveryService.recover` 在一个数据库事务内写入 WorldDefinition、独立 WorldState、来源节点、事件记录和初始检查点；失败回滚，不覆盖正式世界。

StoryCheckpoint 保存该时刻的完整状态和个人记忆；WorldSnapshot 为状态封装。ConversationBranch 记录父世界、来源会话及节点，EventTimeline 单独存储带出处的事件、关系、承诺与秘密。

## 继续与恢复

1. 选择导入对话的最后节点，或任意历史节点。
2. 仅将该节点的祖先链作为本次恢复范围；其他分支原文仍保存。
3. 用户核实身份、当前时间地点、人物、重要物品、事件与伏笔；没有证据的字段不补造。
4. 创建独立世界与初始快照，进入已有聊天运行时。

原始末尾片段可在聊天页展开阅读；未经审核的原文不会被当作公共事实发给所有 NPC。若希望以某段文字作为当前场景，应审核相应候选。关系可保存为可见背景或仅指定人物的知识，不自动把所有私人关系公开。

每个正式完成回合的状态、历史、记忆与新检查点在同一事务提交。取消、网络失败、协议错误或校验失败不提交半轮剧情。初次运行旧存档前会保留当前节点；无法凭空恢复旧版从未保存过的状态。

“恢复到旧节点”采用创建独立分支：复制该时刻状态、个人记忆、此前已完成回合及对应时间线。父世界和之后剧情不变。V0.4 的“重新生成”使用此机制，随后再次确认生成预算；取消预算不会覆盖原回复。

## 数据库与版本

schema4 → 5 新增 world_definitions、world_drafts；schema5 → 6 新增 story_checkpoints、story_branches、timeline_entries、context_summaries。迁移不删旧表或旧世界。V0.4 延续 schema6，不新增重置迁移。

WorldDefinition 以版本追加保存，WorldState 固定其 definitionSnapshot/version。编辑世界只新增设定版本，已有历史不静默变更；界面提示复制新设定进入新故事。旧存档已有内容原样保留，不自动套用新版本。

## 当前边界

- 只有用户审核的内容能确定为恢复事实，不能保证未确认的自然语言已被完整理解。
- 分支/快照随回合增多会占用本地空间；尚无快照压缩与保留策略。
- 完整剧情备份文件未开放，当前导出仅为世界设定，界面明确说明；不把设定导出称为完整存档备份。
- SQLite 文件重开和事务回滚已自动化测试，不能冒充手机强杀进程、ColorOS 后台回收或 iOS 原生恢复实测。
