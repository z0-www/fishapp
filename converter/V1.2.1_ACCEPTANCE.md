## 2. 检查发现的问题

| 级别 | 问题 | 证据/影响 |
| --- | --- | --- |
| P0 | `created_at` / `saved_at` 使用毫秒，Drift 按秒读取 | 恢复后世界日期变成 57974 年；日志/排序异常 |
| P1 | 恢复时 timeline ID 被随机哈希，主 App 按 id 排序 | 原始时间线顺序被打乱，影响后续上下文 |
| P1 | 归档 `customFields.converter.version` 仍是 1.1.0 | 归档元数据与 V1.2.0 APK 不一致 |
| P1 | Service Worker 缓存仍为 `fish-converter-v1.1.0-mobile` | 新版本可能继续使用旧缓存 |
| P1 | 多会话只有 ZIP，主 App 直接文件选择不接收 ZIP | 用户需手动拆分；新增“合并为一个 .yuzhe” |
| P2 | Windows 打包 ZIP 使用反斜杠 | Cloudflare 目录 404；已用 `zip-static.ps1` 修复 |
| P2 | Android 构建在非 ASCII APK 路径上签名/移动失败 | 改为 ASCII 临时签名后生成交付名 |
| — | 图片/附件/工具参数不写入 `.yuzhe` | 预期限制，明确警告 |

## 4. 真实恢复证据

每个有效样本都执行：

```text
parseConversationFile()
  → buildYuzhe()/buildYuzheBundle()
  → 写入真实 .yuzhe
  → StoryBackup.inspect()
  → StoryBackup.restore()
  → Drift AppDatabase 查询
```

没有使用模拟恢复器。

关键结果：

- 100 条消息：100/100 条，角色、正文、顺序、时间戳、timeline 全部一致；
- 1000 条消息：1000/1000 条，首尾和 ordinal 正确；
- 空正文/缺失正文：4/4 条保留，没有静默丢弃；
- TXT 角色对话：4/4 条恢复；
- 多会话 ZIP：3 个独立 `.yuzhe`，每个 2 条，共 6 条；
- 合并 `.yuzhe`：主 App 一次恢复 3 个世界、6 条消息；
- AES-GCM：错误密码失败，正确密码恢复；密文不含正文；
- 重复导入：`BackupFailure`，世界数不增加；
- 预览后损坏：回滚，不污染现有世界；
- 损坏 JSON/ZIP/UTF-8/33 MiB：明确失败，不生成归档；
- 归档元数据：转换器版本 1.2.1；
- 时间戳：`worlds.created_at` / `imported_conversations.created_at` 为 Unix 秒；
- 时间线顺序：`EventTimeline.entries()` 返回源 ordinal 0..N。
